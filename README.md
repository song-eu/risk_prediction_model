# 질환 발병위험 예측 — 웹 배포 가이드

`save_models`가 만든 부스터(JSON)와 레지스트리를 이용해, **브라우저만으로 질환별
1·5·10년 발병 위험을 예측하는 화면**을 공개하는 방법입니다. 서버 없이 정적 호스팅으로
배포할 수 있습니다.

---

## 구성 파일

| 파일 | 역할 | 실행 위치 |
|---|---|---|
| `export_for_web.py` | 부스터(JSON)+레지스트리 → `web_models.json` 변환 | 로컬(파이썬·xgboost 필요) |
| `web_models.json` | 브라우저가 읽는 모델 데이터(트리·σ·보정) | 배포물 |
| `predict.html` | 입력 폼 + 예측 화면(자바스크립트) | 배포물 |
| `README.md` | 본 문서 | — |

> 왜 이런 구조인가: **XGBoost는 브라우저에서 직접 실행할 수 없습니다.** 그래서 부스터의
> 트리 구조를 `web_models.json`으로 내보내고, `predict.html`의 자바스크립트가 그 트리를
> 순회해 예측합니다. 서버·API 없이 정적 페이지로 동작합니다.

---

## 예측 원리 (요약)

각 질환 모델은 XGBoost **AFT 생존모델**입니다. 브라우저는 다음을 계산합니다.

1. **트리 순회** — 입력값으로 각 트리의 잎(leaf)을 찾아 합산 → `margin`
   (결측값은 모델이 학습한 방향(`missing`)으로 분기).
2. **생존확률** — `F(t) = Φ((ln t − margin) / σ)` (Φ=표준정규 누적분포).
3. **보정(calibration)** — 시점별 isotonic 보정을 적용해 실제 발병률에 정렬.
4. **출력** — 1·5·10년 발병 위험 %.

성별 특이 질환(전립선=남성, 유방/자궁=여성)은 성별이 맞지 않으면 자동 제외됩니다.

## 배포 절차

### 1) 로컬에서 모델 변환

`models_saved/`(부스터 `*.json` + `registry_mh.json`)가 있는 폴더에서:

```bash
pip install xgboost numpy          # 이미 있으면 생략
python export_for_web.py           # → web_models.json 생성
```

출력 예:
```
[export] 고혈압       trees=300 feats=48 σ=1.3 base_margin=3.1200
...
저장: /경로/web_models.json (8.4 MB)
```

### 2) 파일 배치

`predict.html`과 `web_models.json`을 **같은 폴더**에 둡니다.

### 3) 공개(정적 호스팅)

아무 정적 호스팅이나 가능합니다.

- **GitHub Pages**: 리포지토리에 두 파일 push → Settings → Pages 활성화.
- **사내 웹서버**: 두 파일을 웹 루트에 복사.
- **로컬 확인**: `python -m http.server` 후 `http://localhost:8000/predict.html`
  (파일을 직접 열면 `fetch`가 막히므로 반드시 서버로 띄우세요).

## 자체검증 (중요)

`export_for_web.py`는 각 질환마다 예시 입력과 그에 대한 **부스터의 실제 예측값**을
`verify`로 함께 저장합니다. `predict.html`은 로딩 시 자바스크립트 예측이 이 값과
일치하는지 검사해 화면 상단에 표시합니다.

```
모델 18개 로드 완료. 자체검증 54건, 최대오차 0.03% ✓
```

- **✓ (오차 < 1%)**: 브라우저 예측이 원본 부스터와 일치.
- **⚠ (오차 큼)**: 변환 문제 → `base_margin` 추출·트리 덤프를 점검하세요.

## 주의·한계

- **진단이 아님**: 통계 모델의 추정치입니다. 화면에 면책 문구가 표시됩니다.
- **이미 유병한 사람**: 해당 질환이 이미 있는 경우 발병 예측은 의미가 없습니다.
  (별도 유병 체크·후처리는 서비스 정책으로 구현)
- **파일 크기**: 트리 수·깊이가 많으면 `web_models.json`이 커집니다(수 MB~수십 MB).
  느리면 `num_boost_round`·`max_depth`를 낮추거나 gzip 호스팅을 사용하세요.
- **입력 결측**: 폼에서 비운 항목은 결측으로 처리되어 모델이 자동 분기합니다.
  실제 서비스에서는 입력 항목을 각 모델의 `features`에 맞춰 구성하세요.
- **민감정보**: 입력값은 브라우저 안에서만 계산되며 서버로 전송되지 않습니다
  (정적 페이지). 별도 로깅을 붙이지 않는 한 개인정보가 외부로 나가지 않습니다.

## 현재 데모

동봉된 `web_models.json`은 **합성(예시) 데이터**입니다(고혈압·비만·전립선암 3종).
실제 배포 시 `export_for_web.py`로 생성한 파일로 교체하세요. `predict.html`은 수정
없이 그대로 사용합니다.
